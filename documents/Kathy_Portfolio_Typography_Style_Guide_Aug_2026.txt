KATHY PORTFOLIO TYPOGRAPHY STYLE GUIDE
Locked Working System — August 26, 2026

PURPOSE
-------
This document is the source of truth for the typography system used across Kathy's UX / Product Design portfolio.

The system is designed to support:
- strong editorial storytelling
- recruiter and hiring-manager scannability
- long-form case study readability
- expressive but controlled visual identity
- project-specific visual worlds
- selective personality without sacrificing clarity

The governing principle:

    SALUTE speaks the major argument.
    FIGTREE structures and explains it.
    ESTHENTIC adds the human aside.

The typography system uses one unified semantic heading scale rather than
separate "display" and "heading" systems. HTML heading level remains
independent from visual type token.


============================================================
1. LOCKED FONT SYSTEM
============================================================

PRIMARY DISPLAY
---------------
Salute
Role:
- homepage hero
- case-study project titles
- major chapter theses
- major narrative turning points
- selected large callouts
- selected large metrics

Working status:
PRIMARY DISPLAY FONT

Important:
- Use the supplied Salute font as Regular / 400.
- Do not fake bold or italic.
- Do not use browser-synthesized 600 / 700 weights.
- Create hierarchy with size, spacing, composition, and Figtree weight instead.


DISPLAY BACKUP
--------------
Gloock
Role:
- licensing / production fallback if Salute cannot be used
- same semantic role as Salute

Working status:
BACKUP ONLY

Reason:
Gloock has stronger immediate drama and visual recognition, but Salute proved more flexible across dense case-study layouts and better suited to a whole-portfolio system.


PRIMARY BODY / UI
-----------------
Figtree

Role:
- body copy
- Subtitle / decks
- navigation
- UI controls
- metadata
- captions
- evidence labels
- case-study supporting headings
- buttons
- tags
- forms
- diagrams
- data labels

Working status:
LOCKED PRIMARY BODY / UI FONT

Reason:
Figtree is readable, contemporary, warm enough to avoid feeling clinical, and neutral enough to let expressive display typography, imagery, atmosphere, and handwriting carry the personality.


BODY / UI BACKUP
----------------
Plus Jakarta Sans

Working status:
BACKUP ONLY

Reason:
Strong readability and contemporary product signal, but more visibly branded / polished than Figtree. It can make the system feel more startup / product-brand oriented and competes slightly more with expressive display typography.


PRIMARY ACCENT
--------------
Esthentic DEMO

Role:
- short handwritten annotations
- human asides
- margin-note moments
- arrows / diagram notes
- occasional expressive microcopy
- selective personal commentary

Working status:
LOCKED FINALIST / PRIMARY WORKING ACCENT

Important:
- Not required for comprehension.
- Never use for navigation, body paragraphs, buttons, critical labels, metrics, or accessibility-critical information.
- Keep use sparse.


ACCENT BACKUP / ALTERNATIVE
---------------------------
Baby Boston

Working status:
LOCKED FOR CONSIDERATION

Reason:
Free, readable, expressive, and similar enough in spirit to the intended personal handwritten feel. Slightly cleaner / friendlier than Esthentic.


REMOVED FROM CONSIDERATION
--------------------------
Display:
- Newsreader — too newspaper / publication-coded relative to the final direction.
- Crimson Pro — too conventionally pretty and not distinctive enough.
- Fraunces — strong and expressive but currently below Salute / Gloock in the final system; can be reconsidered only if needed.

Body:
- Nunito — too soft / rounded relative to the sharper editorial direction.
- Elms Sans — more personality than needed for the body role.
- Carlito — functional but too anonymous.

Accent:
- Caveat — too common.
- Reenie Beanie — useful but surpassed by Esthentic and Baby Boston.
- Covered By Your Grace — louder and more overtly “handwritten font.”
- DearJoe 1 M&S — not part of the final locked pair.


============================================================
2. TYPOGRAPHIC VOICE ARCHITECTURE
============================================================

The typography has three distinct voices.

SALUTE
------
Narrative importance.

Use when the page needs to say:
“This is the idea to remember.”

FIGTREE
-------
Comprehension and structure.

Use when the page needs to say:
“This is what you need to understand.”

ESTHENTIC
---------
Personal interruption.

Use when the page needs to say:
“This is Kathy adding a human note.”

Do not let all three voices compete at once.

The portfolio should feel:

    EXPRESSIVE SHELL
    +
    DISCIPLINED INFORMATION ARCHITECTURE

3. UNIFIED HEADING SCALE
============================================================

The portfolio uses ONE visual heading scale.

Do not maintain separate "Display" and "Heading" systems.
The same visual token may be applied to different semantic HTML heading
levels depending on document structure.

Recommended CSS token names:
- heading-xl
- heading-lg
- heading-md
- heading-sm
- heading-xs
- heading-supporting

Do not name the visual tokens h1 / h2 / h3 / h4 / h5.
Semantic HTML hierarchy and visual emphasis are related, but not identical.

============================================================
5. SEMANTIC USAGE RULES
============================================================

SALUTE SHOULD BE USED FOR
-------------------------
- homepage positioning statement
- case-study project name
- major chapter thesis
- selected high-value narrative turning points
- occasional major callout
- selected major metric

SALUTE SHOULD NOT BE USED FOR
-----------------------------
- every heading
- long-form body text
- UI controls
- forms
- navigation
- dense evidence labels
- captions
- large amounts of metadata

Important:
Salute should feel like a narrative event.
If it appears constantly, it loses its expressive function.


FIGTREE SHOULD BE USED FOR
--------------------------
- all body copy
- Subtitle
- Heading S / Heading XS / Supporting Heading
- product questions
- navigation
- buttons
- project metadata
- data labels
- captions
- charts
- tags
- forms
- functional UI
- evidence interpretation


ESTHENTIC SHOULD BE USED FOR
----------------------------
- short annotation
- brief aside
- expressive human note
- occasional diagram annotation
- arrows or commentary

ESTHENTIC SHOULD NOT BE USED FOR
--------------------------------
- paragraphs
- buttons
- navigation
- labels required for understanding
- accessibility-critical information
- detailed data
- core product copy

============================================================

PARAGRAPH TO PARAGRAPH
----------------------
Approximately 1em


PROSE TO NEW SUBSECTION
-----------------------
Approximately 2–3rem


MAJOR CHAPTER TRANSITIONS
-------------------------
Approximately 6–10rem

Adjust based on:
- anchor visuals
- diagrams
- photography
- narrative pacing


CORE RULE
---------
Not every section should have equal visual intensity.

Quiet sections make major Salute moments stronger.


============================================================
9. EMPHASIS
============================================================

BODY EMPHASIS
-------------
Use Figtree 600.

Use italics selectively if supported.

Avoid:
- excessive colored text
- inserting Salute inside normal paragraphs
- handwriting inside sentences
- bolding entire paragraphs
- multiple competing emphasis devices

If everything is emphasized, nothing is.


============================================================
10. LINKS
============================================================

Font:
Figtree

Keep link treatment simple.

Recommended:
- inherited text color
- visible underline
- slightly increased underline offset
- subtle hover behavior

Avoid stacking:
- dramatic color shift
- underline animation
- background animation
- large motion

Functional interaction should remain obvious and restrained.

    HEADING / SALUTE TYPE FOR INTERPRETATION.
    FIGTREE FOR DATA INFRASTRUCTURE.


============================================================
12. UI CONTROLS
============================================================

All functional controls use Figtree.

Includes:
- navigation
- buttons
- filters
- tags
- pagination
- forms
- dropdowns
- tooltips
- status messages
- accessibility notices

Principle:

    Editorial content can be expressive.
    Interaction should be obvious.


============================================================
13. MOBILE RULES
============================================================

Do not simply shrink desktop typography.

DISPLAY
-------
- allow more line breaks
- reduce scale deliberately
- inspect tracking at narrow widths
- avoid overly compressed letters
- preserve readable rhythm

BODY
----
- never below 16 px
- preferred working target around 17 px for long case studies

METADATA
--------
- avoid going below 12 px
- 13 px preferred where possible

ACCENT
------
- keep annotation copy short
- avoid large multi-line handwritten blocks


============================================================
14. ACCESSIBILITY
============================================================

Typography must remain functional.

Rules:
- body copy minimum approximately 16 px
- body line height at least 1.5
- strong foreground/background contrast
- no essential information presented only in handwriting
- no essential distinction communicated by font choice alone
- page must survive browser zoom to 200%
- display headings must wrap responsively
- no faux Salute weights required for hierarchy
- semantic HTML hierarchy should remain independent from visual style tokens

Important:
Do not force H1 / H2 / H3 styling to determine semantic structure.
Use semantic type classes / tokens.

Important implementation rule:

Do not use h1 / h2 / h3 selectors as the primary visual type system.
Keep semantic HTML structure correct, then apply the appropriate visual token
through classes or component styles.

Use rem for the core type system because rem:
- respects root/user font-size preferences
- keeps sizing predictable across component nesting
- avoids compounding behavior from em-based font sizing

Use em selectively for properties that should scale with the current element,
such as icon size, decorative underline thickness, or local inline spacing.


Production note:
Test Salute → Gloock fallback metrics before placing Gloock directly in the automatic font-family chain.
If the metrics differ enough to damage line breaks or composition, handle fallback intentionally rather than relying on silent substitution.
